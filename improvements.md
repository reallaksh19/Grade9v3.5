## STEP-TA9-001 / AC-TA9-001 — categorical Grade-9 evidence projection

### Goal

Derive, from canonical required scope plus existing learner evidence:

- secure;
- usable-but-fragile;
- known gap;
- insufficient/unknown evidence.

No percentages.

### Primary rules

- proven independent evidence can support secure;
- helped-only evidence cannot become secure independent evidence;
- explicit missing remains a known gap where attribution is valid;
- no observation remains unknown/insufficient, not failure and not mastery;
- enrichment absence remains visible but is not a required Grade-9 blocker;
- session-only READY/REINFORCE/REBUILD must not become persisted grade truth.

### Implementation preference

Prefer a small **derived query/report module** over existing scope/evidence.

Do not add a new learner-state store.

### Required falsifier

- required + proven independent;
- required + helped-only;
- required + explicit missing;
- required + unobserved;
- enrichment + unobserved.

### Stop conditions

Stop if:

- required scope cannot be reconstructed deterministically;
- evidence semantics must be changed rather than consumed;
- implementation appears to require persisted grade mastery.

# 7. Future concept only — self-paced minimal-feedback disclosure

This is the improvement idea that triggered this file.

Grade9V3's programme outcome emphasizes increasing learner independence and little external steering. A later learner-facing falsifier should test whether the host should distinguish:

~~~text
support_available
    canonical help that may safely be offered

support_recommended
    evidence-based suggestion for useful support

support_revealed_or_consumed
    help the learner actually chose to see/use
~~~

Possible later principle:

> Evidence constrains what the system may infer and what help it may safely offer; the learner controls pace and, where practical, whether optional help is consumed.

This is **not current #159 behavior** and must not be implemented from this document alone.

## Future R3 falsifier

For a learner with REINFORCE history:

1. open a fresh R3 body-ownership question;
2. allow a clean independent attempt before optional help is consumed;
3. keep “choose one body first” available;
4. if requested, mark subsequent work as helped;
5. never hand over force ownership prematurely;
6. require fresh independent evidence after help.

A real problem exists only if the learner-facing host automatically exposes support in a way that destroys the protected independent decision.

## Future R8 falsifier

For a learner with prior REINFORCE/REBUILD evidence:

1. open a fresh friction problem with contact state unstated;
2. allow the learner to attempt model choice cleanly;
3. make contact/orientation/force-inventory/static-feasibility help available progressively;
4. never reveal static vs kinetic before the protected decision;
5. treat help-consumed success as non-independent until verification.

## Future retry falsifier

Test whether minimal-feedback UX is better expressed as:

~~~text
incorrect
-> smallest result/diagnostic signal
-> retry
-> optional hint on request
~~~

instead of automatically revealing Hint 1 after every first failure.

Do not change `feedback.py` until real learner-facing evidence demonstrates that the current host behavior is a problem.

## Future exploration-vs-readiness distinction

Potential later distinction:

~~~text
transfer_eligible
    system has evidence to recommend/claim transfer readiness

learner_can_open_transfer
    learner may voluntarily explore a harder problem
~~~

Exploration must never be reinterpreted as proof of prerequisite readiness.
