Core1 · semantic orientation

The canonical surface has exactly three concepts: independent x/y components with one clock, constant acceleration checked per axis, and the gravity-only projectile specialization plus an explicit event condition.

R1 · one event

Separate x from y, but use one frame and one elapsed time. Recombine only simultaneous components.

R2 · per-axis validity

v_x=u_x+a_xt, v_y=u_y+a_yt and matching displacement relations apply only where that axis's acceleration component is constant.

R3 · model then event

Under ideal gravity-only free flight and +y upward: a_x=0, a_y=-g. Then choose apex, same-height return, or actual landing condition before solving.

Boundary: calculus differentiation (Q28), bounce/energy (Q15), altered gravity (Q21), trajectory-equation geometry (Q26), and linear drag (Q23) do not become new canonical microtopics.

Core1A · completed conceptual construction

1 · Independent components / shared clock

Declare one frame → write signed x/y components → keep each axis's quantities separate while sharing one t → recombine only same-time values. Wrong path: “independent” means independent clocks. Repair: attach timestamps before pairing.

2 · Constant acceleration per component

Check a_x and a_y separately → apply the 1D relation only on valid axes → if one axis finds an event time, reuse it on the other. Wrong path: use acceleration magnitude in both equations.

3 · Projectile model and event

Inventory post-release interactions → accept gravity-only specialization only when valid → choose the event condition → reconstruct simultaneous components. At an apex only v_y=0; downward acceleration remains.

Full entry assumptions, inferential jumps, step validity, worked anchors, diagnostics, repairs, independent checks, exit tasks and model answers are in CORE1A.md.
