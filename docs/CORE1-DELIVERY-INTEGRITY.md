# Core1-family learner delivery integrity

Issue: #257  
Programme: #252  
Stack base: Phase‑4 draft PR #263

## Governing delivery contract

The learner-facing progression is:

```text
Core1
compiler-owned semantic orientation map
        ↓
Core1A
completed construction of the canonical inferential jump
        ↓
Core1B
learner prediction/attempt/reconstruction of that same inferential jump
```

Phase 5 does not create new academic truth. It proves that the truth owned by the
canonical library and compiler survives projection, generated data, static hosts and
the browser state machine.

## Provider ownership

Core1-family learner delivery is independent of Core2-family application maturity.

- Core1 projections come directly from the compiler's Core1 orientation product.
- Core1A/Core1B concept coverage comes from compiler concept obligations.
- Core2A/Core2B remain application-question products.
- An optional interactive explorer may enrich a projection but cannot decide whether
  the academic product exists.

This prevents a concept from disappearing from learner delivery merely because no
mature application question happened to reference it.

## Core1 delivery

Core1 is a first-class projection mode. Its payload preserves compiler-emitted:

- orientation text and conventions;
- governing relation meaning, symbols and conditions;
- canonical orientation figure correspondence;
- hard-transition pointers and scope text.

Core1 has no practice application and no learner-attempt gate.

The Phase‑4 relationless-map correction is therefore preserved through delivery:
a bucket whose legitimate map consists of hard-transition/scope content remains
renderable even when it owns no governing equation.

## Core1A delivery

Core1A exposes the completed construction. The projection preserves, when canonical
data supplies them:

- entry assumptions;
- `microtopic.inferential_jump`;
- teaching path and each step's `why_valid`;
- canonical representation refs and picture/word/symbol correspondence;
- misconception → diagnostic → repair claims;
- relation-owned independent checks;
- exit-task closure;
- mapped Core1A worked conceptual anchors.

Missing Phase‑2 authoring remains Phase‑2 migration debt. Phase 5 checks that delivery
does not drop canonical material that already exists.

## Core1B delivery

Core1B changes agency and reveal timing, not conceptual truth.

Before a genuine learner response, the runtime exposes only the authored prediction
and production request. A blank/whitespace response does not count as an attempt.

After commitment the runtime reveals the authored reconstruction cycle:

- defensible prediction answer;
- learner-directed reconstruct asks and their rationale;
- misconception diagnosis and repair;
- declared attempt closure;
- boundary test and what it confirms.

The browser does not substitute Core1A's expert teaching path for the Core1B learner
reconstruction route.

## Static and interactive equivalence

`public/core-learning/index.html` and `standalone/core-learning/index.html` are
generated from one host template and one generated provider. Their only differences
are relative data/runtime paths.

Interactive workbenches/explorers are optional enrichment. Static delivery retains the
same academic projection.

## Completion semantics

Runtime completion is observational only. Learner projections do not contain
mastery, proficiency or readiness state, and the activity-completed event does not
authorize such an inference.

## Deterministic Phase‑5 report

`Shared/library/core1_delivery.py` rebuilds the provider from canonical/compiler
truth and compares it with Phase‑4 progression expectations. It checks:

- every Phase‑4 orientable bucket has Core1 learner delivery;
- every routed study concept has both Core1A and Core1B learner delivery;
- Core1/A/B presentation policies match their semantic roles;
- concept acquisition is not coupled to practice applications;
- Core1B retains the authored elicitation cycle;
- public/standalone hosts are academically identical;
- no mastery/proficiency/readiness state appears in learner projections.

Guardrails requires the committed report to equal a fresh report and requires zero
Phase‑5 delivery findings.

## Upstream debt boundary

Phase 5 does not bulk-repair the existing Phase‑2 construction backlog and does not
silently route `MIC-FRAME-QUALIFICATION-BOUNDARY`. Those remain explicit upstream
programme obligations.
