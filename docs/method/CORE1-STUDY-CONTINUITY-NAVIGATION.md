# I2: Learner-facing Core1 → Core1A → Core1B continuity

Owner programme: [#29](https://github.com/reallaksh19/Grade9v3.5/issues/29) · Integration ledger: [#313](https://github.com/reallaksh19/Grade9v3.5/issues/313).

## Why this is a distinct integration step

The canonical Phase-1–4 audits already establish Core1 orientation buckets and routed Core1A/Core1B concept parity **structurally**. The Phase-5 compiler generates learner CoreProjection records, but the general selector alone does not guide the learner between the three obligations for a *single exact* canonical inferential jump. A QRT-complete practice page and Core1B-only TEST print are not a three-Core learning sequence.

## Live host behavior (not a second curriculum layer)

`Shared/workbench/core1-continuity.mjs` (mirrored to both site runtimes) receives **only** `core_projections` and `bucket_availability` generated by the canonical compiler provider. It does not load topic packages, inspect magic words in mathematical prose, discover a new microtopic, or rewrite truth.

For a selected Core1 map it displays available studied microtopics; for a selected Core1A/B page it displays only that microtopic's path. A path is navigable only when:

1. Exactly one provider `AVAILABLE` bucket contains the selected projection and exactly one Core1 orientation source refers to that bucket.
2. Exactly one Core1A and one Core1B source row share the same subject, bucket and canonical microtopic ID.
3. Core1A and Core1B have identical `inferential_jump`, declared entry assumptions, teaching path, misconception/repair material and canonical representation IDs.
4. Core1A explicitly presents the complete construction without an attempt gate; Core1B is attempt-first with construction withheld and an authored predict → attempt → reconstruct → diagnose/repair → boundary-test cycle.

Missing, duplicate or contradictory data yields a **HOLD**, not a guessed link or a replacement lesson. The existing activity selector remains available; this does not prohibit studying individual authentic projections.

`Shared/tools/build_core_learning_host.py` owns one template for public and standalone hosts. This change adds a keyboard-native navigation region beneath the chooser, publishes both generated host HTML files, and shares the same subject-neutral navigation module with the public/docs runtime. The links navigate to the **exact compiler-generated projection ID**; the previously established Core1B attempt-first web component remains the reveal authority.

## Assistance and independence

Core1A deliberately reveals the complete canonical construction. A learner who views Core1A before Core1B has received **assisted study**, not an uncued independent success. The host displays that rule and, within the live page session, records and discloses when Core1A was viewed for the exact concept. This transient marker is **not durable learner evidence**, a mastery score or a claim that other-tab/previous-session assistance did not occur. The Core1B attempt must be evaluated separately; its model answer remains behind the component's attempt behavior.

This implementation does **not** change existing QRT 7×4 resolution, create ordinary source Core2 or certify any learner, browser screen-reader outcome, formula truth or academic acceptance.
