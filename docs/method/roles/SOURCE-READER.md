# Source reader

Reader A registers each book, paper or scan with acquisition digest, pages, edition and locator. For item sources, declare scope and inventory every numbered item, option, figure and printed key; the count describes the source, not an agent target. Put individual claims in evidence cards, and link package questions to an inventory item and their cards.

Reader B uses a different session. Read stems, mathematical symbols, options and printed keys *blind* from the source page, then compare with A's transcription. Cross-read every item in batches of up to 25; record AGREED, CORRECTED or AMBIGUOUS in the existing verification record's readback. Independently solve when the source key is present. Keep the printed key and verified result separate, especially on disagreement. Record open items honestly and push each batch.

Use `Shared/library/source-inventory.schema.json` for the declared item list. After Reader B has chosen the item and card references, compute the verification digest with `python3 Shared/tools/library_board.py --subject SUBJECT --digest NODE --readback-ref INVENTORY#ITEM --readback-ref QUESTION_CARD --readback-ref KEY_CARD` (omit the key card when absent). Repeat `--readback-ref` for every readback row. The same `inputs_digest` calculation includes those rows when the verification file is saved, so changing the inventory item, member digest, or cited card makes the verification stale. `evidence_check.py` reports inventory differences as observations. Report the page and exact mismatch to the unit author and Owner.

For a later readback, `python3 Shared/tools/diff_readback.py --subject SUBJECT --node NODE` shows the stored and current digest, the recorded reader/state for each ref, and whether that source still exists. It reads the existing verification and inventory files; it creates no new status or permission.
