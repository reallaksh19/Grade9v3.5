# Spec: 10-inch tablet shell and navigation repair

Status: ready for implementation · Audience: an implementing agent with no prior context ·
Owner of acceptance: the two audit tools in §9. Work is done when both pass, not when it looks
done.

This spec is written to be followed literally. Where it says "exactly", copy exactly. Where a
decision is needed that this spec does not cover, choose the option that changes fewer files,
and write the choice in your final report.

---

## 1. Goal

Every page of the deployed site (`https://reallaksh19.github.io/Grade9V3/`, built into `docs/`)
must:

1. be comfortable on a **10-inch tablet** in landscape and portrait, with touch;
2. have one **sticky header** with back, home, breadcrumb, search, display settings (font size,
   zoom %, theme, reduced motion), fullscreen and a menu;
3. be **reachable** from the portal and never be a dead end;
4. work **offline** once loaded: no scripts or styles from other hosts.

### Target devices (CSS pixels)

| Device | Landscape | Portrait | Pixel ratio |
|---|---|---|---|
| Android 10.1" (e.g. Galaxy Tab A) | 1280 × 800 | 800 × 1280 | 1.5 |
| iPad 10.9" | 1180 × 820 | 820 × 1180 | 2 |

Design for **800–1280 px wide**. Pages must still work down to 360 px and up to 1920 px, but
tablet is the optimisation target.

## 4. Design

### 4.1 Site map: the single source of navigation truth

Create `public/data/site-map.js`, written by hand and kept sorted by `path`. Every deployed HTML
page appears exactly once (`404.html` excepted). The audit fails on any page missing from it.

```js
/* Grade9V3 site map. One entry per page under docs/. Edit here, nowhere else. */
window.G9_SITE_MAP = {
  "version": 1,
  "pages": [
    {"path": "index.html", "title": "Knowledge Portal", "kind": "portal", "parent": null, "subject": null, "order": 0, "keywords": ["home"]},
    {"path": "physics/index.html", "title": "Physics", "kind": "subject", "parent": "index.html", "subject": "Physics", "order": 10, "keywords": ["mechanics"]},
    {"path": "physics/motion-2d/index.html", "title": "2D Motion", "kind": "topic", "parent": "physics/index.html", "subject": "Physics", "order": 30, "keywords": ["projectile", "kinematics", "vectors"]},
    {"path": "physics/motion-2d/explorers/shared-clock/index.html", "title": "Shared Clock", "kind": "explorer", "parent": "physics/motion-2d/index.html", "subject": "Physics", "order": 1, "keywords": ["projectile", "components", "time"]}
  ]
};
```

Field rules:

- **`path`:** relative to the site root, always ending in `.html`.
- **`title`:** what a learner calls the page, at most 40 characters. Copy the visible `<h1>`
  when it is sensible.
- **`kind`:** one of `portal`, `subject`, `topic`, `explorer`, `tool`, `bank`.
- **`parent`:** the `path` of the page one level up. Only the portal has `null`. The parent
  chain must reach `index.html` with no cycles.
- **`order`:** sorts siblings. Explorers of one topic are numbered 1, 2, 3 … in teaching order,
  which is the order the topic hub lists them.
- **`keywords`:** lowercase search words, 3–8 per page.
- The file is valid JSON after `window.G9_SITE_MAP =`: double quotes and no trailing commas.
  The audit parses it that way.

### 4.2 Shell files

| File | Purpose |
|---|---|
| `public/css/g9-shell.css` | Theme tokens, header, panels, tablet base rules (§4.6) |
| `public/js/g9-shell.js` | Builds the header, breadcrumb, search, display panel and footer navigation; applies preferences |

A page loads the shell with exactly these two tags, where `ROOT` is the relative path to the
site root: `""` at the root, `"../"` one level down, and so on.

```html
<link rel="stylesheet" href="ROOT/css/g9-shell.css" data-g9-shell-css>
<script src="ROOT/js/g9-shell.js" data-site-root="ROOT" defer></script>
```

At start, `g9-shell.js`:

1. sets `document.documentElement.setAttribute('data-g9-shell', '1')` and, once the page's
   site-map entry is found (step 4), `data-g9-page="<path>"` and `data-g9-kind="<kind>"` on
   `<html>`;
2. reads preferences from `localStorage` (§4.4) and applies them **before** building the UI, so
   there is no flash;
3. loads `ROOT/data/site-map.js` if `window.G9_SITE_MAP` is missing (with a `<script>` tag;
   never `fetch`, so it also works from `file://`);
4. finds this page's entry by matching `location.pathname` against `ROOT` + `path`;
5. builds the header, breadcrumb and footer navigation;
6. exposes `window.G9Shell = {version: '1.0.0', openSearch, openDisplay, prefs}` for tests.

If the page has an old `header.site-nav`, the shell **hides** it (`hidden` attribute) and moves
its subject links into the menu. It never deletes page content.

### 4.3 Header: DOM contract

The audit checks these exact attributes. Do not rename them.

```html
<header class="g9-shell-header" data-g9-shell-header>
  <button data-g9-action="back" aria-label="Back">…</button>
  <a data-g9-action="home" href="ROOT/index.html" aria-label="Home">Grade9V3</a>
  <nav data-g9-breadcrumb aria-label="Breadcrumb"><a href="…">Physics</a> › <a href="…">2D Motion</a> › <span aria-current="page">Shared Clock</span></nav>
  <button data-g9-action="search" aria-label="Search (Ctrl+K)">…</button>
  <button data-g9-action="display" aria-label="Display settings" aria-expanded="false">…</button>
  <button data-g9-action="fullscreen" aria-label="Full screen">…</button>
  <button data-g9-action="menu" aria-label="Menu" aria-expanded="false">…</button>
</header>
```

- **Position:** `position: sticky; top: 0; z-index: 1000`, inserted as the **first child of
  `<body>`**. Height is 56 px, plus `env(safe-area-inset-top)`. Set a CSS variable
  `--g9-header-h` to the real height (use `ResizeObserver`) so pages can offset anchored
  headings with `scroll-margin-top: calc(var(--g9-header-h) + 8px)`.
- **Buttons:** at least 44 × 44 px with 8 px gaps. Icons are inline SVG (24 px) with a visible
  label on screens ≥1100 px wide and the icon only below that, keeping `aria-label`. No icon
  fonts.
- **Breadcrumb:** built from the site-map parent chain. At widths under 900 px, show only the
  parent and the current page ("‹ 2D Motion › Shared Clock").
- **Back:**
  - If `document.referrer` is on the same site root, it calls `history.back()`.
  - Otherwise it goes to the site-map `parent`.
  - Otherwise it goes to `ROOT/index.html`.
  - It never leaves the site.
- **Fullscreen:** uses `document.documentElement.requestFullscreen()`. Hide the button when
  `document.fullscreenEnabled` is false (iPad Safari).
- **Menu:** a panel listing:
  - the subjects, Question Bank and Tools;
  - "Recently opened", the last 5 pages from `g9.recent`;
  - "Report a problem on this page", linking to
    `https://github.com/reallaksh19/Grade9V3/issues/new?title=Page%20problem:%20<path>&body=<url-encoded path and viewport size>`
    and opening in a new tab.

  This link is the only allowed off-site navigation. It is a link, not a request.

### 4.4 Display panel and preferences

The panel (`[data-g9-display-panel]`) opens under the header and closes on Escape, on an outside
tap, or on the display button.

| Control | Attributes | Values | Effect |
|---|---|---|---|
| Font size | `data-g9-font="dec" \| "inc" \| "reset"` | scale steps `0.9, 1, 1.1, 1.25, 1.4, 1.6` (default `1`) | `html { font-size: calc(17px * var(--g9-font-scale)) }` |
| Zoom | `data-g9-zoom="dec" \| "inc" \| "reset"`, plus a live "100%" label | `0.8`–`1.5` in steps of `0.1` (default `1`) | `html { zoom: var(--g9-zoom) }` |
| Theme | `data-g9-theme="dark" \| "light" \| "contrast" \| "sepia"`, as radio buttons | default `dark` | `html[data-theme="…"]`, with tokens in §4.5 |
| Reduce motion | `data-g9-motion="reduce"`, a switch | on/off; default follows `prefers-reduced-motion` | `html[data-motion="reduce"]` disables CSS transitions and animations |
| Reading width | `data-g9-width="narrow" \| "wide"` | default `wide` | `narrow` limits `main`/`article` to `72ch` and centres them |
| Reset all | `data-g9-reset` | — | removes every `g9.pref.*` key |

Preferences:

- They are stored in `localStorage` under `g9.pref.font`, `g9.pref.zoom`, `g9.pref.theme`,
  `g9.pref.motion` and `g9.pref.width`.
- Wrap every read and write in `try/catch`; the page must work with storage blocked.
- Listen for the `storage` event so other tabs update.
- Also set `--g9-zoom` and `--g9-font-scale` on `<html>`. The audit reads `--g9-zoom`, and it
  must read exactly `1.1` after one "inc" from default.
- **Migration:** on first load, if `grade9v3_font_scale` or `grade9v3_ui_scale` exist, copy
  them to the nearest new step, then delete the old keys.

Notes:

- **Font size** affects text sized in `rem`/`em`. Explorers use fixed `px`, so for them **zoom**
  is the control that works. Say so in the panel as help text under the font control: "Font
  size affects reading pages; use Zoom for simulations."
- **Zoom** scales the whole page including the header, like browser zoom. After changing it,
  drag a slider or handle in `physics/motion-2d/explorers/shared-clock/index.html` at 80% and
  150% and confirm the handle follows the finger. If an explorer mis-tracks, add its path to
  `NO_ZOOM_PAGES` in `g9-shell.js`, where zoom is fixed at 1 and the zoom buttons are disabled
  with the note "Use pinch-zoom on this page". Record each exception in your report.

```css
html[data-theme="light"]      { --g9-bg:#ffffff; --g9-surface:#f6f8fa; --g9-text:#1f2328; --g9-muted:#57606a; --g9-line:#d0d7de; --g9-accent:#0969da; --g9-focus:#bf8700; color-scheme: light; }
html[data-theme="contrast"]   { --g9-bg:#000000; --g9-surface:#000000; --g9-text:#ffffff; --g9-muted:#ffffff; --g9-line:#ffffff; --g9-accent:#ffd33d; --g9-focus:#ffd33d; color-scheme: dark; }

```

- The header, panels and footer navigation always use these tokens.
- In `public/css/site.css`, map its existing variables to these tokens (for example
  `--bg: var(--g9-bg)`) so hub pages follow the theme. **Do not change their layout while
  doing this.**
- Explorers keep their own colours; only the header follows the theme there. This is
  intended. Do not restyle explorers.
- Every text colour must meet WCAG AA contrast (4.5:1) on its background in all four themes.
  Check the four themes on the portal and one hub page with any contrast checker, and list
  the results in your report.

### 4.6 Tablet base rules (in `g9-shell.css`, applied to every shell page)

```css
html { -webkit-text-size-adjust: 100%; }
body { margin: 0; background: var(--g9-bg); color: var(--g9-text); padding-bottom: env(safe-area-inset-bottom); }
a, button, [role="button"], summary, input, select { touch-action: manipulation; }
input, select, textarea { font-size: max(16px, 1rem); }        /* stops iPad focus-zoom */
img, svg, video, canvas { max-width: 100%; height: auto; }
:focus-visible { outline: 3px solid var(--g9-focus); outline-offset: 2px; }
html[data-motion="reduce"] *, html[data-motion="reduce"] *::before, html[data-motion="reduce"] *::after { animation: none !important; transition: none !important; scroll-behavior: auto !important; }
```

**Canvas exception:** some explorers size a `<canvas>` with attributes, and `height: auto` can
distort it. Scope that rule to `img, svg, video` if any explorer's canvas changes aspect ratio,
and record it.

Layout rules for hub and portal pages (in `public/` source, not explorers):

| Rule | Value |
|---|---|
| Base text | 17 px (`1rem` after the shell); body line-height 1.55 |
| Smallest text anywhere | 14 px, including badges and chips (the tag rows in the screenshot are 11 px today) |
| Tap targets | ≥ 44 × 44 px, ≥ 8 px apart; links inside running text are exempt |
| Card grids | `display: grid; grid-template-columns: repeat(auto-fill, minmax(320px, 1fr)); gap: 20px` gives 3 columns at 1280, 2 at 800 |
| Content width | `max-width: 1200px; margin-inline: auto; padding-inline: clamp(16px, 3vw, 32px)` |
| Tables | wrap in `<div style="overflow-x:auto">`; the page itself never scrolls sideways |
| Hover | nothing may exist only on hover; every hover effect also appears on `:focus-visible` and needs no hover to be usable |

### 4.7 Search

- **Trigger:** `[data-g9-action="search"]`, `Ctrl/⌘+K`, or `/` when focus is not in a text field.
- **Dialog:** a `<dialog>` containing `input[data-g9-search-input]` and
  `[data-g9-search-results]`. Each result is an `<a href>` at least 48 px tall.
- **Sources:**
  1. site-map pages, matching on title, keywords and subject;
  2. questions from `ROOT/data/question-bank-data.js`, loaded lazily with a `<script>` tag.
     Match on id, topic, exam, year and stem. Question results link to
     `ROOT/question-bank/index.html?q=<id>&mode=study#<id>`, as today.
- **Ranking:** title prefix, then title contains, then keyword, then stem. Show at most 6 pages
  and 8 questions.
- **Empty query:** show "Recently opened" from `g9.recent`.
- **Keyboard:** ↑/↓ move through results, Enter opens, Escape closes. Focus returns to the
  search button on close.
- **Acceptance:** typing `projectile` on any page returns at least one link.

### 4.8 Footer navigation for explorers

On pages of `kind: "explorer"`, append a sticky bottom bar `nav[data-g9-sibling-nav]` with three
parts:

- **"‹ Previous"**: the previous sibling by `order`. Omit it on the first explorer.
- **the topic hub title**: links to `parent`.
- **"Next ›"**: the next sibling. Omit it on the last explorer.

Each item is ≥ 44 px tall. Add bottom padding equal to the bar's height so it never covers
content.

### 4.9 Recently opened

On every load, push `{path, title, at}` to `localStorage['g9.recent']`. Keep at most 5 entries,
with no duplicates and the newest first.

### 4.10 404 page

Create `public/404.html`; GitHub Pages serves it for unknown URLs. It must include:

- the shell (header with search);
- the heading "This page moved or does not exist";
- a search box that opens the search dialog;
- links to the portal, Physics, Chemistry, Mathematics and Question Bank.

Its asset links must work from any depth, so resolve `ROOT` in `g9-shell.js` from the script's
own `src`.
