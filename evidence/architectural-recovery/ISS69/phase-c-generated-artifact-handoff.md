# ISS69 PHASE-C — C03.6 governed generated-artifact handoff

Current Phase-C branch: `fix/iss69-phase-c-runtime-alignment`

## Source-of-truth rule

Generated learner/compiler artifacts remain owned by repository generators. They MUST NOT be hand-edited to make Phase-C checks green.

The authoritative regeneration path is:

```text
python3 Shared/tools/build_manifest.py
```

`build_manifest.py` calls, in order, the governed generators for:
- web data;
- Core-learning projection data;
- Core-learning host;
- Core-learning runtime;
- derived Core-projection registry;
- architecture manifest.

Its `--check` mode recomputes intended bytes in memory and treats freshness separately from semantic authority.

## Why they are not edited here

The connected GitHub environment exposes repository file writes and CI result reads, but not arbitrary execution of `python3 Shared/tools/build_manifest.py` on this branch.

The existing `.github/workflows/pass1-refresh-generated.yml` is not a valid substitute:
- it is hard-wired to `question-bank/pass1-provenance`;
- it checks out that branch explicitly;
- its commit step stages only `tools/data.js`, `public/data/data.js`, and `docs/architecture-manifest.json`;
- it does not stage `public/core-learning/data.js` or the full governed generator output set.

Changing that unrelated workflow merely to manufacture Phase-C bytes would create another authority/workflow side path.

## Required regeneration handoff

Before Phase-C final promotion:

1. checkout the exact accepted Phase-C material head;
2. run `python3 Shared/tools/build_manifest.py`;
3. review the generated diff as GENERATED/MECHANICAL;
4. confirm `python3 Shared/tools/build_manifest.py --check` returns clean;
5. run the Core-learning projection contract tests;
6. mirror/deploy through the existing pages/publication path;
7. refresh exact digests/receipts after the generated-byte commit.

Any generated artifact that still names Core1A 1.7.0 after that procedure is a generator defect, not a file to patch manually.
